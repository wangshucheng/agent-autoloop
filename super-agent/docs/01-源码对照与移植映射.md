# 01 源码对照与移植映射

> 依据：本地源码快照 `.research/agent-autoloop/`（约 1651 行内核、零运行时依赖、Node 24）
> 与 `.research/dsh-superagent-prototype/`（TypeScript + pnpm，绑定 DeepSeek Harness 插件宿主）。
> 本文回答：**哪些照搬、哪些重表达、哪些必须放弃**。

## 1. 两个仓库到底各有什么

### 1.1 agent-autoloop（底座，可运行的产品）

| 维度 | 事实 |
| --- | --- |
| 语言/运行时 | TypeScript，Node 24，运行时依赖 0，`node:sqlite` |
| 内核规模 | `kernel/` 约 1651 行（含注释空行）；`decide.ts` 621 行是唯一决策入口 |
| 核心机制 | 挂起零消耗、事件溯源、指令数据分离、跳数熔断（`MAX_HOPS = 8`，`kernel/decide.ts:41`） |
| 状态模型 | 单条只追加 `facts(seq, fact)`；`evolve(view, facts)` 是唯一投影写者；`View` 支持 `fork()` 覆盖层；`projection_meta` 存游标/编号高水位/格式指纹 |
| 事务 | `commit()` 在同一 `BEGIN IMMEDIATE` 里做 CAS 校验（`MAX(seq) === view.seq`）→ 追加事实 → `evolve` → `COMMIT` 后才应答（`kernel/store.ts:35`） |
| 协议 | HTTP + JSON，三个口子：来源 `POST /v1/events`、接单程序 `GET /v1/work`、通道 `GET /v1/cards/next`；本人 `GET /v1/state`；SSE `GET /v1/stream?after=`；`GET /v1/runs/42/why` |
| 六个词 | 事件 / 规则 / 事项(rule+lane+grp) / 一轮(run) / 回执(receipt) / 卡片(card) |
| 规则 | `~/.agent-autoloop/rules.json`：`when{cron|source+types}`、`to`、`cwd`、`skill`、`prompt`、`group`、`parallel`、`tell`、`emits`、`askFirst`、`sources`、`agents`、`channels` |
| 回执 | Agent 最后一条消息里的 `agent-autoloop` JSON：`ask / notice / resolve / later / events`，一个事务里一次生效 |
| 插件 | 统一入口 `plugins/<name>/{agent,channel,source}.ts`；仅用 `node:` 模块；事件插件只翻译不发请求；凭据留在插件 |
| 安全 | 事件带 `cwd/agent/access` 直接拒收；`subject`/`link` 字符白名单才进提示词；`summary/detail` 只进资料文件；访问密钥只存 SHA-256；`master.key` 推导轮次/卡片 token |
| 失败 | 底座 `docs/protocol.md` 有一张 25 行失败表（重复事件、丢响应、重派退避、会话续接、规则写错、数据库锁、日志写不出去等） |
| 性能基线 | 冷启动 88.78ms，空闲 59.94MB，持久化 2394 条/秒，派活 p99 1.82ms，110 万事实启动 99.8ms |
| 明确没有 | 总览页、工作流画布、Agent 记忆、模型路由、**多租户/多项目**、插件市场（`docs/protocol.md:373`） |
| 平台 | macOS / Linux；Windows 版当时待定；macOS 用 launchd、Linux 用 systemd（`host/service.ts:1`） |

### 1.2 dsh-superagent-prototype（设计思想，研究原型）

README 自称 research prototype、非官方产品、可能与文章描述不一致。它绑定 DeepSeek Harness 插件宿主（`cordis.patch.yml`、`dsh` CLI、`gh`、`lark-cli`），**代码不能整体搬迁**，可移植的是领域模型与约束。

| 维度 | 事实 |
| --- | --- |
| 理念 | `docs/000-philosophy.md`：「Take as little human attention as possible, and give as much value as possible」；只按请求或书面规则行动；只在人必须行动或能用结果时说话；一次只问一个具体问题；健康状态不占版面 |
| 领域模型 | `docs/001-domain.md`：Source / Trigger / Thread / Correlation / Channel / Policy / Eval / Mandate / Ticket / Assignment / Subscription |
| 流 | Source → Trigger → Thread → Eval(gate + assessment) → Ticket(Mandate) → Assignment → Executor → Channel |
| Eval 两层 | `Gate`（确定性：谁可发起、`strength=explicit|inferred|not admitted`、admission 表） + `Assessment`（主会话模型研判） |
| 接受模式 | `off / observe(默认) / auto`；`observe` 只记录「would accept」不接单；`auto` 才真正接推断型工作 |
| 授权 | `Mandate` 不可变，记录 `policy_version / scope / strength / matched_rules / basis`；只有三种操作能改变：accept 创建、人停止撤回、**复验失败撤销** |
| 复验 | 结束的 Ticket 被人消息唤醒前，按当前 Policy 重新校验（规则仍启用、发送人仍在名单、bot 仍在 bot list、`auto` 模式） |
| 主会话 | `orchestrator` 角色；14 个工具；`orchestrator_eval*` 三件套；`MasterAssessor`（`src/app/assessment.ts`）通过 `assessment` effect 把候选卡送进主会话；显式请求**不评估**，直接 `orchestrator_route` |
| 超时 | Eval 从候选送达主会话开始计时；连续两次超时重排，第三次记 `unavailable`；Policy 变更会丢弃在途 Eval 并重排 |
| 执行 | 一 Ticket 一 `worker-<id>` 会话 + 一目录（git worktree）；`WorkerSlots` 并发槽，人的消息可多用 1 个额外槽并优先；后台 job 30 分钟上限 |
| 副作用 | `Effects`（`src/app/effects.ts`）：**先存后做**，`(kind,key)` 单行合并，`Later` 不计失败，指数退避；6 种 kind：assessment / launch / delivery / relay / notice / reply |
| Outbox | 消息按 `Ticket + 会话` 顺序发送；3 次连续失败才报系统问题；会话消失时 `dropped` 保留原因，永不重排 |
| Health | `HealthBoard`（`src/infra/health.ts`）：每条健康条目由唯一认领者写，重复认领被拒 |
| 面板 | `docs/005-panel.md`：三个问题（要我做什么 / 系统健康吗 / 这件事的历史），六个 Tab；「A healthy state takes no space」；问题必须可行动 |
| 架构约束 | `src/core` 不做 I/O、只依赖自身；`src/sources` 不 import `src/app`；一个状态一个写者；角色用 `Pick<Engine>` 收窄；请求用祈使、上报用过去式 |
| 持久化 | 单 SQLite `orchestrator.sqlite`，11 张表/KV，**明确没有删除旧记录**，会无限增长 |
| 已知开放问题 | `docs/007` 末尾自列：哪些 Trigger 字段可信、部署隔离 |

## 2. 共同点与冲突点

| 维度 | 共同 | 冲突（必须裁决） |
| --- | --- | --- |
| 理念 | 都把「人的注意力」当最贵的资源 | — |
| 事件 | 都以不可变事件为审计单位 | 底座是**单条事实日志 + 可重建投影**；dsh 是**多张聚合表 + SQLite 事务** |
| 确定性 | 都强调可复现 | 底座内核零 I/O 且不重跑规则；dsh Engine 同步事务但评估器出网 |
| 挂起 | 底座「问完进程退出」 | dsh 的 Executor Session 常驻，用 `worker slot` 管理（不适合直接搬） |
| 授权 | 底座一轮一 token；事件不能指定权限 | dsh 有完整 Mandate/复验/撤销模型（**要移植**） |
| 人机界面 | 底座卡片/CLI，无界面；dsh 有面板 | 目标要「预留接口」的 Web 后台，取 dsh 的信息架构，不取它的 React 代码 |
| 宿主 | 底座独立进程 | dsh 是 DSH 插件，依赖 `dsh` / `gh` / `lark-cli` / `cordis.patch.yml`（**全部放弃**） |
| 多项目 | 底座明确无多租户 | dsh 只服务一个 GitHub 仓库（**两者都不能直接用，需新增**） |

**裁决：以底座的事实日志为唯一真相，把 dsh 的领域对象重表达为「投影 + 事实类型」。** 理由：两套持久化并存必然出现双写不一致，而底座的崩溃重放/格式指纹/模拟测试是已经验证过的资产，丢掉它等于丢掉整个底座价值。

## 4. 明确放弃的 dsh 部分

| 放弃项 | 原因 |
| --- | --- |
| DeepSeek Harness 插件宿主、`cordis.patch.yml`、`dsh` 预设与 Session API | 与底座独立进程模型冲突；底座已用 `plugins/dsh/agent.ts` 把 DSH 当一个 CLI Agent 接入 |
| `src/app/store.ts` 的 11 表聚合存储、`schema 11 migration` | 与底座单日志冲突；底座格式指纹重建已替代迁移脚本 |
| `src/executor/background.ts` 的 session job/subagent 管理 | 依赖 DSH 运行时；底座用「一轮一进程 + 回执」表达，长任务由 worker 跟到真正做完 |
| `src/client/` 全部 React 面板 | 绑定 DSH 客户端 UI 原语；目标只要预留接口 |
| `src/sources/feishu*.ts` / `github*.ts` 的 CLI 耦合实现（`lark-cli`、`gh`） | 底座已有 `plugins/feishu`、`plugins/github`；保留「Source 只翻译、不发请求」的约束，重写实现 |
| `SETUP.md` 引导式安装 | 底座用 `install.sh` + `agent-autoloop doctor` |
| 单仓库假设 | 目标要求多项目，改为 `project_id` 命名空间 |

## 6. 移植顺序（依赖倒置，先纯后 I/O）

```
M0  fork + 基线跑通（底座 npm test / conformance / benchmark 全绿）
     │
M1  L0 纯函数：approval.ts / excitation.ts / grants.ts + Fact v2 schema
     │           （此时不开 LLM、不开 Web，纯单测可验证确定性）
     ▼
M2  L1/L2 领域：threads/tickets/grants/decisions 投影 + Intake/Gate/Router
     │           + Effects/Outbox + Policy 版本
     ▼
M3  Assessor（主会话 LLM，DeepSeek）+ 审批卡片开关 + 挂起复验/撤销
     ▼
M4  Watchdog + Dashboard/Blackboard 预留接口 + 多项目 + 飞书卡片联调
     ▼
M5  WSL → macOS 迁移、性能回归、长跑与自激压测
```

每阶段都必须保持底座的模拟 / 强杀 / 变异三套检查全绿，否则不许进入下一阶段。

## 7. 调研中发现的、必须写进设计的坑

1. **底座明确「没有多租户/多项目」**（`docs/protocol.md:373`）。多项目是本次真正的架构增量，不能靠多开实例糊弄。
2. **底座「至少一次」语义**（`docs/protocol.md:267`）：Agent 可能被调用两次，所有有副作用的 Skill 必须先核实当前状态；移植 dsh 的 Outbox 顺序保证时要保留这个前提。
3. **dsh 的存储无限增长**（`docs/007` 末尾自承）。底座日志同样只追加不压缩。本项目要在 M5 加**分支 GC + 冷归档**，否则审计日志会先撑爆磁盘。
4. **dsh 自列开放问题「哪些 Trigger 字段可信」**：本项目用 `taint` + 字段白名单明确回答，见 `docs/03 §5`。
5. **底座 `command` 插件不提供系统沙箱**（`docs/plugins.md:107`）：`access` 只是 CLI 参数的翻译，不是安全边界。设计文档不得把它当成隔离能力。
6. **飞书卡片链接是「持有即授权」**（`SECURITY.md:16`）：7 天有效，不能发到公开位置；多项目时更要按项目限制 `answerers`。
7. **dsh 的 `observe` 默认模式值得照搬**：它是「最小注意力」最实用的一条工程落点——先只记录「本来会接」，人看过再切 `auto`。
